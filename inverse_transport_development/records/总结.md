# 总结

## 阶段定位

该目录用于承接 RL_Enhanced 当前阶段成果之后的下一阶段研究开发，重点包括：

1. 由已规划载荷轨迹反推绳索驱动力。
2. 由绳索驱动力与系统几何约束进一步反推无人机位置与编队关系。

## 当前状态

- 已完成独立开发区目录初始化。
- 已建立记录、参考文献、主源码、实验、数据、配置、结果、测试等基础结构。
- 已确定第一版 wrench 框架输入：以“时间戳 + 位置轨迹”为统一主输入，速度与加速度为可选显式输入。
- 已确认现有规划输出包含 `sample_t`、`sample_xyz`、`coeffs_x/y/z`、`T_per_seg`，可直接接入 wrench 推断。
- 已新增第一版源码骨架：`src/common/`、`src/cable_force_inference/`、`experiments/`、`tests/`。
- 已补第二版 wrench 接口骨架：支持载荷几何尺寸占位、由 box 尺寸恢复惯量、以及基于角速度/角加速度的刚体力矩恢复。
- 当前 torque 恢复仍不包含绳索受力点与受力分配模型，后续需依据论文补 attachment geometry。
- 已补 attachment geometry 接口：支持 `r_i`、`L_i`、`q_i` 的显式表达，支持式 (5) 的无人机位置恢复，以及 body frame 下的 `Phi` 映射矩阵构造。
- 已补真实规划输出接线脚本：优先读取 `corridor_export.mat`，回退支持 `sample_t/sample_xyz`，可直接生成 payload wrench、挂点力与 UAV 位置结果图。
- 已新增碰撞优先 UAV 反推建模文档：`records/碰撞优先_安全走廊_UAV反推建模.md`，系统整理了安全走廊、张力可行性、轨迹可控性与分层优化公式，可作为后续实现和论文总结的主说明文档。

## 后续建议起点

2. 收集并整理相关论文与开源实现到 `references/`。

5. 下一步在 attachment geometry 之上补正张力约束与张力分配，再把 torque 与 UAV 几何反解闭合起来。

## 仿真环境路线结论（2026-06-04）

- 对当前“载荷轨迹 -> wrench -> 绳索张力 -> UAV 位置反推”阶段，优先使用 Python/NumPy/SciPy 做核心动力学、优化和可行性验证；不要把 Gazebo GUI 作为日常算法开发入口。
- Gazebo/ROS 更适合作为后期三维回放、接口验证和系统集成层；当前 VS Code/Snap/GLVND/Qt 环境容易把 GUI 问题误判成算法问题。
- 公开参考中最贴近多机吊载运输的是 RotorTM：README 明确定位为 aerial transportation and manipulation simulator，包含 full system dynamics、planning/control、cable suspended load hybrid model、payload trajectory 接口和 attach mechanism 参数。
- RotorS 是成熟 MAV/Gazebo 底座，适合无人机级控制与传感器仿真，但不是专门的吊载反推平台。
- gym-pybullet-drones 适合 Python/RL 快速验证和多机控制原型，但需要自行扩展吊载/绳索动力学。
- Crazyswarm2 更偏 ROS 2 + Crazyflie 真实多机执行栈，适合作为远期硬件落地路线，不适合作为当前建模首选。
- 推荐路线：核心算法在 Python 独立闭环验证，阶段性用 Matplotlib/Plotly/Rerun 可视化；需要机器人系统接口时优先对照 RotorTM；最终展示或集成时再进入 ROS/Gazebo。

## 碰撞优先 UAV 反推建模（2026-06-10）

- 当前 `point_force_allocation.py` 仅提供“给定 payload wrench 的最小范数挂点力分配”，不能等价视为碰撞安全且物理可执行的 UAV 规划。
- 对本项目更合理的问题定义应改为：在障碍膨胀得到的安全走廊内，规划三架 UAV 的位置轨迹，并强制满足机间防碰撞、张力上限与轨迹可控性约束。
- 建议采用分层求解：外层做碰撞优先的 corridor 轨迹优化，内层做 `Phi(q) T = W` 与 `0 <= T <= T_max` 的张力可行性检查。
- 该问题整体更接近 sequential convex programming，而不是单个纯 QP；QP 适合作为每一轮局部凸子问题。
- 与现有代码的接口已经明确：`wrench_models.py` 提供 `W_L`，`rigid_body_payload.py` 提供 `r_i/L_i/Phi`，`point_force_allocation.py` 退为初值或基线，不再作为最终 UAV 轨迹生成器。

## 文档目标项对齐补充（2026-06-16）

- 已把文档 `9.3` 中的四项目标在代码里补到第一版可执行形态：`J_ref + J_smooth + J_shape + J_tension`。
- `J_shape` 当前实现为 pairwise 相对位形保持项，直接约束 `(x_i^k - x_j^k)` 不偏离参考编队相对位移，用于防止三机局部退化。
- `J_tension` 当前实现已从“统一同权重位置吸引”收紧为“每轮在当前参考上先做内层张力评估，再按各时刻残差大小生成样本权重 `\alpha_k` 的位置 surrogate”。
- 已新增单元测试覆盖这两项行为：一条验证张力 surrogate 的按样本加权生效，一条验证 shape 正则相对无正则基线时更保形。 

## 张力残差线性化与 trust region（2026-06-16）

- 已进一步把外层 `J_tension` 从纯位置 surrogate 收紧为“固定当前参考张力解后的残差一阶线性化项”，即围绕当前参考 `\bar{X}` 构造 `\bar{r}^k + J_r^k(x^k-\bar{x}^k)` 的局部二次目标。
- 该线性化项当前通过有限差分构造 `J_r^k`，并继续复用按样本残差大小归一化的权重 `\alpha_k`，使张力困难时刻在外层 QP 中获得更强校正。
- 已在局部 QP 中加入盒式 trust region `\|x_i^k-\bar{x}_i^k\|_\infty \le \Delta_{tr}`，用于控制线性化有效域，避免单轮更新步长过大。
- 验证结果：`python3 -m unittest tests.test_uav_pose_inference` 现为 6 项通过；`python3 experiments/run_collision_aware_uav_demo.py` 的残差历史已从先前约 `[0.263, 0.261, 0.259, 0.257]` 显著收紧到 `[0.040, 0.031, 0.026, 0.022]`，mean residual 约为 `2.20e-2`。
- 当前剩余主差距：严格张力可行仍未达到，当前仍为 relaxed feasible；此外 trust region 还是固定半径，尚未做基于实际/预测下降比的自适应更新。
