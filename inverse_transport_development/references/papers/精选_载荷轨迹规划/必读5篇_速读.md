# 必读 5 篇速读

目标不是系统读完所有文献，而是在时间有限的情况下，先抓住能直接支撑下面这条研发主线的最小文献集合：

1. 载荷轨迹 -> 载荷所需 wrench。
2. 载荷 wrench -> 多绳索张力分配。
3. 张力与绳索几何 -> 无人机位置反推。
4. 前向仿真/回放验证反推结果是否自洽。

## 1. K.S2013(326)RSS(经典建模参考).pdf

为什么必须先读：

- 这是多无人机通过绳索协同运输刚体载荷的经典动力学建模入口。
- 你后面所有“反推”几乎都要先建立在它这一类前向动力学关系上。

你现在最该看什么：

- 载荷平动和转动方程怎么写。
- 每条绳索的方向、张力、挂点位置如何进入动力学方程。
- 状态变量和控制输入在论文里是怎么分层定义的。

你看完后应得到什么：

- 一套清晰的变量表：载荷位姿、速度、角速度、绳索方向、张力、挂点坐标。
- 明白“先求 payload wrench，再分配到 cable tensions”为什么是合理路线。

暂时可以先不深究：

- 具体控制器设计细节。
- 复杂稳定性证明。

## 2. K.W2024(15)IEEE_RAL(待细看，很全).pdf

为什么必须读：

- 这篇最直接卡住你当前任务的中间层，也就是 cable force allocation。
- 你的难点不是只有动力学，而是“总 wrench 已知时，多根绳索怎么分力”。

你现在最该看什么：

- 张力分配问题被写成什么优化问题。
- 非负张力、上下界、冗余自由度是怎么处理的。
- 文中有没有给出可行 wrench 或约束可行域的表达。

你看完后应得到什么：

- 第一版张力分配模块应采用的数学形式，大概率是带约束优化而不是解析唯一解。
- 明确后续代码里至少需要哪些输入：挂点、绳索方向、目标 wrench、张力约束。

暂时可以先不深究：

- 高阶实验对比。
- 复杂实时实现细节。

## 3. T.L2017(214)IEEE_TCST(几何控制).pdf

为什么必须读：

- 这篇能帮助你把“载荷级”与“飞行器级”之间的耦合关系看得更清楚。
- 如果只看建模和分力，不看几何控制，你后面容易把状态层级混在一起。

你现在最该看什么：

- 几何关系中载荷姿态、绳索方向、飞行器推力方向之间的映射。
- 哪些量是独立变量，哪些量是由几何约束决定的。
- 负载、绳索、无人机之间耦合最强的部分在哪里。

你看完后应得到什么：

- 对“由绳索方向和挂点反推 UAV 位置”这件事的几何直觉。
- 一份更不容易写错的变量依赖关系图。

暂时可以先不深究：

- 完整控制律推导。
- 所有稳定性证明细节。

## 4. Y.W2026(5)TranOnRobot.pdf

为什么要进前五：

- 这篇更偏系统级协同运输，能帮助你判断最终目标是不是只停在“分出一组张力”，还是要落到真正可执行的多机协同运动。
- 它更接近你未来会面对的系统层可行性问题。

你现在最该看什么：

- 文中如何描述多机协同运输场景。
- 是否讨论了安全运输、快速机动、编队几何或运输执行约束。
- 它对载荷级规划和执行级控制之间的接口是怎么组织的。

你看完后应得到什么：

- 对你最终系统目标的上限预期。
- 明白第一版模型该简化到什么程度，第二版该往哪里扩展。

暂时可以先不深究：

- 所有实验场景细节。
- 与你当前开发无关的完整控制栈实现。

## 5. G.L2023(36)IEEE_Tran_on_R(仿真工具，参考建模).pdf

为什么要留在前五：

- 这篇不是理论核心，但它决定你后面怎么验证。
- 你做“轨迹 -> 张力 -> UAV 位置”反推，如果没有前向验证平台，很容易停留在纸面正确。

你现在最该看什么：

- 仿真器里 payload、MAV、attach mechanism 的参数组织方式。
- 轨迹接口、外力/外 wrench 接口、系统状态输出接口。
- 哪些模块能直接作为你后续代码结构参考。

你看完后应得到什么：

- 你自己的 src 目录后续该如何分模块。
- 反推结果最终需要怎样的前向检查接口。

暂时可以先不深究：

- ROS 具体部署步骤。
- 全部仿真功能和 launch 细节。

## 10 分钟阅读顺序

如果你现在时间极少，按这个顺序扫：

1. 先看 `K.S2013...`，只抓建模变量和主方程。
2. 再看 `K.W2024...`，只抓张力分配怎么建模。
3. 再看 `T.L2017...`，只抓几何耦合关系。
4. 然后扫 `Y.W2026...`，确认系统级目标长什么样。
5. 最后看 `G.L2023...`，明确后续怎么验证。

## 一句话结论

如果只能记住一句话，那就是：

先用 `K.S2013 + K.W2024` 把“轨迹 -> wrench -> 张力”做扎实，再用 `T.L2017` 补几何耦合，用 `Y.W2026` 决定系统扩展方向，最后参考 `G.L2023` 搭验证环境。
