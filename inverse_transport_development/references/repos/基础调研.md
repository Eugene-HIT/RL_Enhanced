# 基础调研

## 调研目标

筛选对下一阶段开发最有价值的开源仓库，重点不是数量，而是它们是否能帮助完成以下任务：

1. 验证多机-绳索-载荷动力学建模。
2. 验证张力分配与编队反推结果。
3. 作为后续仿真或系统落地平台。

## 证据来源

本文件当前内容主要基于各仓库 GitHub README 页面。

## 推荐优先级

### 1. RotorTM

仓库：

- https://github.com/arplaboratory/RotorTM

来源依据：

- 仓库 README 自述其为 aerial transportation and manipulation simulator。
- README 明确写到 full system dynamics、planning and control algorithms、hybrid model for cable suspended load。
- README 提供 MAV 参数、payload 参数、attach mechanism 参数，以及 payload desired trajectory 接口。

为什么最值得优先看：

- 这是当前筛到的最贴近你任务目标的公开实现。
- 它同时覆盖载荷、绳索连接机制、轨迹接口和控制链路，适合核对“反推模型是否能接入前向仿真”。

对你当前开发的具体价值：

- 可用于对照多机载荷动力学状态定义。
- 可用于检查张力/外力接口应该放在哪一层。
- 可作为未来验证“由轨迹反推的张力与无人机位置”是否可执行的候选平台。

限制与注意：

- README 指向 ROS Noetic/Melodic + Python 3.8 路线。
- 与当前 Windows 工作环境不直接一致，更适合作为参考实现或后续 Linux 仿真底座。

### 2. RotorS

仓库：

- https://github.com/ethz-asl/rotors_simulator

来源依据：

- README 将其定义为 modular Gazebo MAV simulator。
- README 明确提供 multirotor models、simulated sensors、example controllers、basic worlds 和 example launch files。

为什么有价值：

- 虽然不是吊载运输专用，但它是成熟的多旋翼仿真底座。
- 如果后续需要自己扩展绳索/载荷插件，RotorS 是稳妥候选。

对你当前开发的具体价值：

- 适合作为后续系统级验证或自定义插件宿主。
- 适合验证无人机级控制与轨迹执行，而非直接提供逆推算法。

限制与注意：

- README 主要面向 ROS + Gazebo 传统工作流。
- 它更偏平台基础设施，不是现成的吊载反推实现。

### 3. gym-pybullet-drones

仓库：

- https://github.com/learnsyslab/gym-pybullet-drones

来源依据：

- README 将其定义为 PyBullet Gymnasium environments for single and multi-agent reinforcement learning of quadcopter control。
- README 明确提到兼容 gymnasium 与 stable-baselines3，并提供 PID、RL、多机示例与测试入口。

为什么有价值：

- 你当前工程已经有 Python + SB3 + 研究原型的基础，这个仓库与你现有技术栈更近。
- 它适合低成本搭建轻量验证环境，快速做“反推后再前向回放”的实验闭环。

对你当前开发的具体价值：

- 适合做小规模 Python 侧验证。
- 适合保留和当前 RL 工作流相近的工程节奏。

限制与注意：

- README 没有表明其原生支持 cable-suspended payload。
- 若采用，需要你自行扩展绳索和载荷动力学。

### 4. Crazyswarm2

仓库：

- https://github.com/IMRCLab/crazyswarm2

来源依据：

- README 将其定义为 A ROS 2-based stack for Bitcraze Crazyflie multirotor robots。

为什么有价值：

- 它更偏向真实多机执行栈，而不是运输专用仿真器。
- 如果未来要把“反推得到的无人机位姿/编队”落到实际多机平台，它有中长期价值。

对你当前开发的具体价值：

- 当前阶段主要作为后续硬件执行路线储备。

限制与注意：

- 不是当前第一阶段建模与逆推实现的优先入口。

## 当前建议的使用顺序

1. 先把 RotorTM 当成最贴题的参考实现阅读对象。
2. 把 RotorS 当成后续高保真仿真底座候选。
3. 把 gym-pybullet-drones 当成 Python 侧快速验证底座候选。
4. 把 Crazyswarm2 当成更后期的实验执行栈储备。

## 后续动作建议

1. 下一轮优先精读 RotorTM 中与 payload dynamics、trajectory、attach mechanism 相关的模块。
2. 如需轻量验证，则尽快评估是否在 Python 环境中自建一个最小 forward-check 仿真器，而不是过早切到 ROS/Gazebo。
3. 等张力分配和无人机几何反解跑通后，再决定是否接入 RotorS 或真实多机栈。
